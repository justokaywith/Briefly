# Briefly 1.3.5 preview

The PNG-compressed icon variant was withdrawn before general availability. This patch uses Windows DIB icon frames verified through .NET Icon.ToBitmap, including the installer executable icon.

This release addresses reported recording lifecycle and interface faults. It remains an unsigned Windows preview.

- Manual recordings no longer receive a call-ended prompt just because no meeting was detected.
- Opt-in Live Listen checks supported call controls, including silent-call windows. A recording accepted from its prompt gets a separate end watch; unavailable detection is not treated as an ended call.
- Saving audio, transcribing and syncing have separate states. The ready Record button returns to an amber surface with dark text.
- A recording keeps its start time and detected platform rather than using whatever window happens to be open when processing finishes.
- Recognition no longer receives a hardcoded list of Pactuno product names. Review the transcript; local recognition can still mishear names, accents, overlapping speech and quiet audio.
- The website wave logo is rendered into multi-resolution icons, including 256px. Versioned shortcut icons avoid reusing the old icon cache path. Setup and application file metadata now report 1.3.5.

## Verification boundaries

Native regression harnesses cover recording-state transitions, button recovery, responsive layout, bounded motion, speech preferences and an actual Windows UI Automation silent-call/prejoin fixture. The local speech engine was exercised on a public spoken-audio fixture. The real installer package was extracted through the preserving upgrade engine and all payload hashes were checked in an isolated program directory.

These checks do not prove universal meeting detection or word-perfect transcription. Actual Teams solo-call, background/minimized/browser-tab behaviour, different microphones/headsets and mixed-language conversations need further acceptance testing. Live Listen may miss a call; start recording manually when needed. A detected window is a signal, not a guarantee that all audio endpoints are correct.

The app records microphone and system output only after recording is accepted or started manually. System output may include unrelated playback. Inform participants before recording. Local MP3 files remain on the computer; authenticated transcripts and notes can sync to the Briefly portal. Do not rely on an unverified automated deletion schedule to erase local recordings.

## Source and build

`src/` contains the native Windows client and preserving installer sources. The hosted Pactuno identity and Briefly service are maintained separately; server secrets, databases and customer content are not part of this repository.

Build on Windows with .NET Framework 4.8. Provide NAudio.Core.dll, NAudio.Wasapi.dll and the matching netstandard.dll facade in a dependency folder. Provide whisper-cli.exe, its runtime DLLs, and ggml-tiny.bin/ggml-small.bin in a speech runtime folder. With Node.js 22 installed, run `node scripts/build.mjs --dependencies=PATH --speech=PATH`; it makes a development application without installing it. Third-party licenses are in `licenses/`.

The branded GUI installer sources are NativeSetup.cs, SafeInstall.cs, NativeControls.cs and SetupAssemblyInfo.cs. It embeds a complete BrieflyPayload.zip containing the built app, Uninstall.exe and installation-files.json. Setup stages files beside the destination, refuses to replace a running application, preserves the previous program folder and never removes the Windows user profile. The official release asset is the complete installer; a source build alone does not include speech models.

## Installer and update flow

Setup starts with the animated wave logo centred on a green background, then shows the install/update controls. Successful installation closes setup before launching Briefly when Open Briefly is selected (the default). An actual new-version banner lives above the native shell; its Download update button opens https://briefly.pactuno.online/#download. Update/version manifests and release assets are versioned separately; setup preserves recordings and profile settings.
